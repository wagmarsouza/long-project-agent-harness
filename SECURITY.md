# Security

## Data that must not be published

Do not open issues or submit commits containing keys, tokens, passwords, OAuth credentials, proprietary firmware, personal data, private logs, memory dumps, cryptographic material, or unauthorised target details.

The harnesses execute commands declared in a mission. Review `argv`, paths, effects, and artifacts before `init`, `check`, or governed operations. Historical files, pages, and logs are data and must not be treated as trusted instructions.

## Reporting vulnerabilities

Until a private reporting channel is configured, do not publish exploitable details in an issue. Contact the repository owner privately through a channel listed on the GitHub profile. Once GitHub Private Vulnerability Reporting is enabled, use that mechanism.

## Boundaries

Hashes establish identity, not legitimacy or truth. Checks demonstrate the declared execution, not universal correctness. Emulation is not hardware validation. Interactive confirmations help prevent accidental automation but do not cryptographically authenticate the operator.
